Linux 性能（八）文件系统与磁盘 I O 工作原理

发表于 2023-08-23 分类于 性能优化
本文字数： 4.4k 阅读时长 ≈ 4 分钟

引言

磁盘和文件系统这一层，最容易被跳过的是原理，最容易被用错的是指标。磁盘空间明明还有，文件却创建不出来，往往是 inode 用尽；%util 到了 100%，也不一定就该换盘——它只统计有没有 I/O，不管请求多大。这篇把从应用到磁盘的整条 I/O 栈拆开，看清每一层做什么、缓存放在哪，再辨析阻塞/非阻塞与同步/异步这两组常被混用的概念，最后落到 df -i、iostat、/proc/diskstats 这些观测点。本篇锚点那组数——CPU 三成、P99 800 毫秒——在 I/O 层对应的是请求排队等磁盘，而不是算力不够。

文件系统与 I O 栈

Linux 里一切皆文件，普通文件、目录、块设备、套接字、管道都走统一的文件系统接口。文件系统管理文件靠两个结构：索引节点（inode）记录文件大小、权限、修改时间、数据位置这些元数据，和文件一一对应，存在磁盘上；目录项（dentry）记录文件名、inode 指针和目录关系，由内核维护在内存里，也就是目录项缓存。一个文件可以有多个目录项——硬链接就是不同名字指向同一个 inode。

目录项、索引节点与磁盘逻辑块的关系

磁盘读写的最小单位是扇区，512 字节，一次读写这么小块效率太低，文件系统就把连续扇区组成逻辑块，常见 4 KB，作为最小管理单元。磁盘格式化后划成三个区：超级块存整个文件系统的状态，索引节点区存 inode，数据块区存文件数据。

为了兼容 Ext4、XFS、NFS 这些实现各异的文件系统，内核在应用和具体文件系统之间加了虚拟文件系统 VFS，定义统一的数据结构和接口。应用只需跟 VFS 打交道，不必关心底层是哪种文件系统。

Linux 文件系统架构：系统调用、VFS、缓存与块设备

最底下的设备层，磁盘分机械和固态两类。机械盘靠磁头在盘片上寻道，连续 I/O 省去寻址最快，随机 I/O 要反复移动磁头，慢得多；固态盘没有机械寻址，随机性能远好于机械盘，但有「先擦除再写入」的限制，随机写会触发垃圾回收，同样比连续写慢。所以两类盘的随机 I/O 都逊于连续 I/O，只是差距大小不同。机械盘最小读写单位是 512 字节的扇区，固态盘是页，常见 4 KB 或 8 KB。

再往上还有一层通用块层，它处在文件系统和磁盘驱动之间，向上提供访问块设备的标准接口，向下把各种磁盘抽象成统一块设备，还负责给 I/O 请求排队、排序、合并——这就是 I/O 调度。它支持四种调度算法：NOOP 是简单先入先出，常用于固态盘；CFQ 为每个进程维护队列、按时间片分配，适合进程多的桌面环境；DeadLine 给读写分队列、保证请求在期限内完成，多用于数据库这类 I/O 压力重的场景；NONE 则完全不调度，常见于虚拟机，把调度交给物理机。整条栈自上而下是文件系统层、通用块层、设备层。

flowchart TD
    A["应用程序"] --> B["系统调用 open/read/write"]
    B --> C["VFS 与页缓存 / 目录项缓存 / 索引节点缓存"]
    C --> D["具体文件系统 Ext4 / XFS / NFS"]
    D --> E["通用块层 I/O 队列 + 调度器"]
    E --> F["设备层 磁盘驱动与存储设备"]
    E -.-> G["缓冲区 Buffer"]

I/O 分类常按四个维度切：是否用标准库缓存，分缓冲与非缓冲 I/O；是否用系统页缓存，分直接（O_DIRECT）与非直接 I/O；是否阻塞调用线程，分阻塞与非阻塞 I/O（O_NONBLOCK）；是否等待完成结果，分同步与异步 I/O（O_SYNC、O_ASYNC）。这四组是不同角度的划分，彼此正交。

df -i 与容量假象

文件系统最常见的故障是空间不足，但有两类「不足」长得不一样。用 df 看块空间，另有 inode 的使用情况要单独看。

inode 数量在格式化磁盘时就定好了。当磁盘空间还富余、df -i 却显示 inode 用满，多半是海量小文件造成的——每个文件不管多小都要占一个 inode。这时删掉多余小文件，或把它们移到 inode 充足的其他磁盘，空间自然就腾出来了。只看 df -h 的百分比，会以为磁盘还有大把空间，找不到创建文件失败的原因。

缓存这一侧，索引节点和目录项都由 Slab 管理，/proc/meminfo 只给 Slab 总量，细分要到 /proc/slabinfo 看。页缓存和可回收 Slab 的大小则直接从 meminfo 读。

iostat 与 diskstats 观测点

磁盘性能看五个指标：使用率、饱和度、IOPS、吞吐量、响应时间。使用率是处理 I/O 的时间占比，饱和度是繁忙程度，IOPS 是每秒请求数，吞吐量是每秒请求大小，响应时间是从发出到收到响应的间隔。使用率到 100% 时磁盘仍可能接受新请求，因为它只统计有没有 I/O、不管大小；饱和度到 100% 才真的接不了新请求。

iostat 是最常用的观测工具，数据来自 /proc/diskstats。

几个换算要记牢：r/s + w/s 是 IOPS，rkB/s + wkB/s 是吞吐量，r_await + w_await 是响应时间，%util 是使用率。分析时还要结合请求大小 rareq-sz 和 wareq-sz——小文件多的随机读写场景看 IOPS 更准，顺序读写为主的多媒体场景看吞吐量更准。饱和度 iostat 给不出来，拿平均队列长度 aqu-sz 或等待时间和 fio 的基准结果比，才能估算。

进程这一级用 pidstat -d 或 iotop。前者给出每个进程的读写速率和块 I/O 延迟，后者按 I/O 大小排序找大户。iostat 只看磁盘整体，回答不了「是谁在读写」，这一步得靠这两个工具补。

同步异步与阻塞的混淆

四组 I/O 概念里，最常混的是阻塞/非阻塞和同步/异步。前者针对调用者——应用发出 I/O 后，线程是挂起等待还是继续干活；后者针对执行者——系统处理完 I/O 后，是用系统调用返回结果，还是用事件通知。

flowchart LR
    A["一次 I/O"] --> B{"调用者线程是否挂起"}
    B -->|"挂起"| C["阻塞 I/O"]
    B -->|"不挂起"| D["非阻塞 I/O"]
    A --> E{"结果如何通知"}
    E -->|"等待完成后返回"| F["同步 I/O"]
    E -->|"事件或回调通知"| G["异步 I/O"]

read 是同步读，拿到磁盘数据前不返回；aio_read 是异步读，系统先返回，结果通过回调通知。套接字 send 默认阻塞，设了 O_NONBLOCK 就不阻塞，配合 epoll 可以在不可写时转去处理别的套接字。两组维度可以组合，非阻塞的调用照样可能用同步方式返回结果，轮询就是这种情况；把它当成异步，会在结果何时到达上判断错。

观测工具本身也会出错。用 strace 跟踪一个多线程进程的 write，可能一条都看不到，加 -f 跟踪所有线程才有结果。工具的输出不合理时，先检查选项和原理，别急着下结论。

本篇锚点里 CPU 三成、P99 800 毫秒，在 I/O 层对应请求排队：应用发出读请求后挂起等待，CPU 闲着，延迟却全堆在等磁盘上。查法是从 iostat 看整盘是不是忙、从 pidstat -d 找出读写大户，再判断是随机小 I/O 还是顺序大 I/O，决定该调调度、合并请求还是扩容量。

小结与参考

文件系统用 inode 存元数据、dentry 维护目录树，两者经 VFS 接入，之下还有通用块层负责排队、排序和合并，I/O 栈分文件系统层、通用块层、设备层三层。inode 在格式化时定量，小文件过多会先耗尽 inode 而非块空间。磁盘性能看使用率、饱和度、IOPS、吞吐、响应时间五项，iostat 给出其中几项的换算，进程维度要用 pidstat -d 或 iotop 补。阻塞/非阻塞看调用者线程是否挂起，同步/异步看结果如何通知，两组维度正交互不替代。
